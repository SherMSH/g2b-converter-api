# Workflows — индекс

> **Назначение:** список ключевых бизнес-процессов проекта. Каждый процесс — отдельный файл с пошаговым описанием.
> **Обновлено:** 2026-08

---

## Как пользоваться

- Один процесс = один файл.
- Имя файла: `kebab-case`, отражает суть (`pin-change.md`, а не `process1.md`).
- В таблице ниже — одна строка на процесс с кратким описанием.
- Новый процесс → создать файл по [шаблону](#шаблон-нового-процесса) + добавить строку в таблицу.

## Общее для всех процессов

- Ошибка любого шага ONLINE-процесса превращается в SOAP Fault и прерывает выполнение — компенсаций и ретраев нет.
- Идемпотентность обеспечивается только для финансовых операций через `ecTxRefno`.
- Ни один процесс не пишет собственное состояние: см. [Database.md](../Database.md).

## Шаблон нового процесса

Используй структуру файла [online-soap-conversion.md](./online-soap-conversion.md) как образец. Минимально процесс должен содержать:

1. **Контекст** — зачем процесс существует.
2. **Триггер** — что его запускает.
3. **Участники** — какие пакеты и функции задействованы.
4. **Шаги** — пронумерованный список с указанием слоя.
5. **Альтернативные сценарии** — ошибки, edge cases.
6. **Side effects** — что происходит за пределами основного потока.
7. **Диаграмма** — sequence diagram через Mermaid.
